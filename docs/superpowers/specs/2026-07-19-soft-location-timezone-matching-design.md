# 国家与时区软匹配设计

## 背景

当前匹配流水线先通过 pgvector 召回语义最相关的 200 个职位，再执行确定性硬过滤。
`hard_filter()` 会因候选人国家不在职位允许范围内或候选人时区不满足职位要求而淘汰职位。
当语义召回结果集中缺少中国或亚洲时区职位时，即使数据库里存在其他可推荐职位，也可能返回零条匹配。

本次调整的目标是避免国家和时区信息导致候选职位被全部淘汰，同时继续利用这些信息改善排序质量。

## 行为设计

国家和时区从硬过滤条件改为软评分条件：

- `country_mismatch` 不再由 `hard_filter()` 返回。
- `timezone_mismatch` 不再由 `hard_filter()` 返回。
- `score_match()` 现有的 `location_timezone` 分项保持不变。
- 国家和时区都匹配的职位在该分项获得更高得分。
- 只匹配一项或两项均不匹配的职位仍可生成匹配结果，但排序分数相应较低。

其余硬过滤规则不变：候选人授权、职位状态、风险审核、排除公司、工作模式、语言、薪资、工时以及已发送职位仍可淘汰职位。

## 数据流

调整后的匹配流程为：

1. 使用候选人的技能、目标角色和简历概要生成向量。
2. 通过 pgvector 召回语义相关职位；向量不可用时保持全量扫描降级行为。
3. 使用剩余硬规则淘汰不可推荐职位。
4. 对通过硬过滤的职位计算包含 `location_timezone` 在内的多维得分。
5. 按总分排序并返回结果。

本次不修改 pgvector 查询接口、召回窗口大小或职位数据模型。

## 兼容性与可解释性

现有 API 响应结构保持不变。`filtered` 列表中将不再出现 `country_mismatch` 和
`timezone_mismatch`。现有 `score_breakdown.location_timezone` 字段继续说明地区与时区对总分的影响。

规则行为变化需要更新 `RULE_VERSION`，使新生成的匹配记录与旧规则结果可区分、可审计。

## 测试

增加以下回归覆盖：

1. 国家和时区均不匹配时，`hard_filter()` 不返回对应失败原因。
2. 国家和时区均不匹配但其余条件满足时，`run_matches()` 仍生成匹配结果。
3. 其他条件相同的职位中，国家和时区匹配的职位得分高于不匹配职位。
4. 既有授权、风险、语言、薪资和工时等硬过滤测试继续通过。

## 不在范围内

- 不删除候选人或职位上的国家、时区字段。
- 不完全忽略国家与时区对排序的影响。
- 不修改简历解析器对国家和时区的提取方式。
- 不增加用户侧筛选开关。
- 不调整召回数量或实现零结果回退。
