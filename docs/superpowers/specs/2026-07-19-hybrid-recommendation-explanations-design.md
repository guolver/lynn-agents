# 混合推荐理由设计

## 背景

当前匹配引擎会计算技能、语义、语言、地区与时区、薪资、工时、职位偏好和职位质量八个维度，
但推荐理由只在少数维度达到较高阈值时生成。部分岗位因此只展示“语言符合”或“地区与工作时区满足要求”，
没有解释候选人的技能、经历、目标职位、薪资和可用工时如何影响推荐。

本次调整的目标是让每张岗位卡同时具备自然、个性化的推荐总结和可验证的结构化依据，且不改变匹配结果本身。

## 展示结果

每条聊天岗位推荐包含两层解释：

1. `recommendation_summary`：一句个性化中文总结，说明候选人的核心优势与岗位需求之间的联系。
2. `reasons`：最多五条确定性依据，明确列出技能、经历语义、职位方向、薪资、工时、语言、地区时区或职位质量等证据。

前端在岗位卡上方展示总结，在卡片内部以标签展示确定性依据。总结缺失时不显示空白占位，依据仍正常展示。

## 确定性依据

`score_match()` 继续负责生成 `reasons`，依据只来自已有候选人、职位和评分数据：

- 直接技能：列出候选人与职位要求中直接重合的技能。
- 关联技能：列出通过技能图谱扩展命中的职位技能。
- 经历语义：根据现有 semantic 分数区分“高度相似”和“具有相关性”。
- 语言：职位有语言要求且候选人全部满足时生成理由。
- 地区与时区：只描述实际满足的部分；不把不匹配描述为优势。
- 薪资：职位薪资达到候选人最低期望时生成理由。
- 工时：候选人可用工时满足职位要求时生成理由。
- 职位方向：候选人目标角色与职位类别直接重合时生成理由。
- 职位质量：质量分达到高质量阈值时说明职位信息较完整、可信度较高。

理由按与候选人匹配的解释价值排序，最多保留五条。信息不足时允许少于三条，不使用虚构或泛化理由凑数。
现有低完备度提示是风险说明，不计入五条正向依据上限，并继续保留。

## LLM 批量总结

新增独立的推荐解释器模块。聊天工具完成 `run_matches`、并把职位详情补充到 match 后，解释器对本次前五条结果执行一次批量 DeepSeek 请求。

输入仅包含：

- 候选人的目标角色、技能和简历概要；
- 岗位标题、公司、职责摘要；
- 已生成的确定性依据。

模型必须返回以 `job_id` 为键的 JSON 对象，每个值是一句不超过 120 个中文字符的总结。提示词明确禁止增加输入中不存在的经历、技能、薪资或岗位事实。解释器只接受本批次已有的 job ID，并丢弃空值、非字符串、超长值和未知 ID。

一次请求同时处理前五条岗位，不为每个岗位单独调用模型。超过五条的匹配仍保留确定性依据，但不生成个性化总结。

## 组件边界

- `domain.py`：扩展确定性理由生成，不依赖网络或 LLM。
- 新增 `recommendation_explainer.py`：组装批量提示、调用 DeepSeek、验证 JSON 输出并返回 `{job_id: summary}`。
- `chat_tools.py`：在 `run_matches` 富化职位详情后调用解释器，把总结写入返回的 match。
- `chat-message.tsx`：读取 `recommendation_summary`，分别渲染总结与理由标签。

通用 AgentService、硬过滤、评分权重、排序、pgvector 召回、数据库模型和 REST API 结构不做破坏性修改。
`recommendation_summary` 作为 match payload 的可选字段传播；旧会话和旧 match 没有该字段时继续兼容。

## 降级与性能

以下情况均静默降级为只有确定性依据，不让匹配失败：

- `DEEPSEEK_API_KEY` 未配置；
- 请求超时或供应商错误；
- 模型输出不是合法 JSON；
- 输出缺少部分岗位或包含未知岗位；
- 单条总结不满足类型和长度约束。

降级事件记录 warning 日志，但不把异常暴露给用户。解释器使用有限超时；每次匹配至多新增一次模型请求。

## 测试

后端覆盖：

1. 多维信息充分时生成技能、语义、语言、薪资、工时、方向或质量等不同类型依据。
2. 理由最多五条，且不为零分或不满足维度生成正向理由。
3. 低完备度提示继续保留。
4. 批量解释器构造一次请求并正确映射 job ID。
5. 未配置密钥、模型异常、非法 JSON、未知 ID 和超长总结均安全降级。
6. 聊天工具把合法总结附加到对应 match，失败时仍返回原始匹配。

前端覆盖类型检查和构建，确认有总结、无总结以及旧历史数据都可渲染。

## 不在范围内

- 不让 LLM 修改匹配分数、排序、硬过滤结果或确定性依据。
- 不为每个岗位单独调用模型。
- 不回填已有数据库 match 或历史聊天消息。
- 不在本次增加用户开关、模型选择或提示词管理界面。
