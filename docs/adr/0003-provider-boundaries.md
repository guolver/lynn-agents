# ADR 0003: LLM、Embedding 与通知 Provider 边界

- 状态：已接受
- 日期：2026-07-17

## 背景

职位抽取、语义召回和真实通知会依赖外部服务。供应商 SDK、网络失败、模型版本和返回格式不稳定；如果它们进入领域规则或应用服务，测试、替换供应商和审计都会变得困难。

## 决策

为三类能力建立独立可替换边界：

- `LLMProvider`：结构化抽取、翻译或解释生成，返回经过 schema 校验的结果及模型元数据。
- `EmbeddingProvider`：批量生成固定维度向量，记录模型、维度和版本。
- `NotificationProvider`：发送已审批消息，接收幂等键并返回稳定的 provider message ID。

Provider 接口由应用层调用，具体 SDK 只存在于适配器。自动化单元测试使用本地 fake，不访问外部网络。确定性的授权、风险拒绝、硬过滤、评分、审批和最终发送资格检查始终由领域/应用代码决定；LLM 输出不得覆盖这些规则。

## 后果

- 可以在不修改业务用例的情况下更换供应商或增加本地实现。
- Provider 结果需保存版本、输入关联、错误和可审计元数据。
- 调用方必须定义超时、重试、限流和错误映射；日志不得泄露候选人敏感信息。
- 通知成功只能由可持久化的 provider message ID 确认，并受业务幂等约束保护。
