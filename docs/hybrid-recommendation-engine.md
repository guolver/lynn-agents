# 混合推荐引擎：规则过滤 + RAG 语义检索

构建"规则过滤 + RAG 语义检索"的混合推荐引擎，首先根据地区、时区、薪资、语言和工时排除不符合条件的职位，再使用 pgvector 检索与候选人技能和项目经历相似的职位，提升非关键词场景下的召回能力。

## 整体流程

```
全部职位
  │
  ▼ 规则过滤（快，精确）
符合硬性条件的职位（比如 1000 → 200）
  │
  ▼ pgvector 语义检索（慢，智能）
按相似度排序的推荐列表（Top N）
```

简单说：**先用规则砍掉不可能的，再用 AI 从剩下的里找最匹配的**。

## 第一阶段：规则过滤（硬性条件筛选）

用确定性规则先排除明显不匹配的职位。

| 规则维度 | 示例 |
|---------|------|
| 地区 | 候选人在中国，职位要求美国本地，直接排除 |
| 时区 | 职位要求 UTC-5 工作时间，候选人无法覆盖，排除 |
| 薪资 | 候选人期望 5 万，职位上限 3 万，排除 |
| 语言 | 职位要求日语，候选人不会，排除 |
| 工时 | 候选人只能每周 20 小时，职位要求全职，排除 |

这一步是**粗筛**，速度快，把明显不合格的过滤掉。项目中 `domain.py` 里的纯确定性规则做的就是这件事。

## 第二阶段：RAG 语义检索（pgvector 向量相似度）

过滤后剩下的职位，用**语义相似度**来排序推荐。

### 传统关键词匹配的问题

- 候选人写"React 开发 3 年"，职位写"前端工程师"→ 关键词不重叠，匹配不上
- 候选人写"做过分布式爬虫"，职位写"数据采集平台开发"→ 同一件事，词不一样

### pgvector 的做法

1. 把候选人的**技能 + 项目经历**转成向量（embedding）
2. 把职位描述也转成向量
3. 用向量相似度计算（余弦距离）找出语义最接近的职位

这样即使用词不同，语义相近的也能匹配上，这就是所谓的"提升非关键词场景下的召回能力"。
